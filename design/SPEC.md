## 1. 目标与非目标

**目标**：给一个人用的美股和港股研究工作台。输入一个股票代码，它能拉齐带来源的数据，组装财报包，让 Claude 写解读和假设，再由固定规则算出 A/B/C 三档买点、仓位和周收盘失效位，生成可复查的报告；之后每周五自动对照观察清单，只在需要行动时提醒。验收用三个真实案例回放：INTC 和 GOOGL 2026 年第三季度财报（2026-10-28、10-29 发布），以及联想 0992 在 2026-10-29 定的三档买点，都是本项目已经写好的分析。

**需求对照**：

| 需求 | 设计里的位置 | 验收 |
|---|---|---|
| 分析股票情况：价格、估值、技术位 | [DATA]、[VAL]、[TECH] | [AT-3]、[AT-10] |
| 解读财报：实际 vs 预期、指引、电话会 | [EARN] 出数字，[SKILL] 读电话会写判断 | [AT-1]、[AT-2]、[AT-5] |
| 给出具体买点：分档价位、仓位、失效位 | [ZONES] | [AT-3]、[AT-4] |
| 结论可信：不用过期价格、不在数据不全时下结论 | [QA] | [AT-4] |
| 能复用、能定时跑 | [SKILL]、[SCHED]、[WATCH] | [AT-7]、[AT-8] |
| 云端和你的 Mac 都能用 | [DATA] 两条取数路 | [AT-5]、[AT-10] |
| 港股进第一版（如联想 0992） | [R-HKEX]、[DATA]、[VAL] 的汇率换算 | [AT-10]、[AT-12] |

**非目标**：

- 不接券商、不下单。工具只产出研究结论，买不买由你决定。
- 不做多空打分黑箱。不输出“综合评分 78 分”这类数字，只输出带依据的价位。
- 不做实时盯盘和日内交易。最细的粒度是日收盘，复盘按周收盘。
- 港股只做主板个股，不做 A 股、不做窝轮和牛熊证。
- 不买付费数据（2026-10-30 你定的）。电话会实录、港股一致预期这类免费来源不稳定的字段，按非关键字段处理，拿不到就在报告里写明。
- 以上产出都是研究记录，不构成投资建议。

## 2. 关键决策

1. **数字由代码算，判断由 Claude 写**。借鉴 FinRobot 的原则。财报数字、估值、价位全部是确定性的 Python 计算；Claude 负责读电话会、判断指引、给出 EPS 和 PE 的假设。这样同样的输入永远得到同样的价位，可以测试。
2. **分析只读快照，不直接联网**。所有外部数据先由 [DATA] 写成带来源的快照，分析内核只通过 [QA] 读快照。好处：可以回放历史，可以断网测试，云端和 Mac 跑同一套代码。
3. **两条取数路，同一种快照**。Mac 上 [DATA] 直连来源。云端的 Python 联网被拦（2026-10-30 实测：sec.gov、stockanalysis.com、FRED、雅虎全部连不上），所以云端由 Claude 用 WebFetch 抓网页，抽成 JSON 后 `sd import`。两条路写出的快照格式完全相同。
4. **宁可不出结论，也不出错误结论**。UZI-Skill 在数据覆盖率 12% 时仍给出高分，用的还是财报前的价格。2026-10-30 用 WebFetch 读 stockanalysis 的联想页面，拿到的也是 10 月 20 日的价格，说明网页缓存同样会给旧数据。本项目由 [QA] 在每次分析前检查覆盖率、时效和来源一致性，不通过就停下并说明缺什么。
5. **用真实案例做验收**。INTC 和 GOOGL 2026 年第三季度的财报数字和三档买点，本项目已人工核对过，作为“标准答案”回放。新代码必须复现它们。
6. **买点规则沿用现有方法**。与主报告第 2 章和 GOOGL、INTC 两份分析一致：A 档贴近支撑或 50 日线，B 档贴近 200 日线或估值底，C 档只在恐慌时用；财报跳空后等 2 个交易日；失效位按周收盘。规则参数写在配置文件里，改参数不改代码。
7. **报告沿用现有样式**。HTML 版式参照 `googl-q3-2026.html` 和 `intc-q3-2026.html`，由 Claude 发布成报告页。
8. **仓库放 GitHub 私有仓库**（2026-10-30 你已确认），云端会话和你的 Mac 用同一份代码和数据。
9. **港股和美股走同一条流水线，差异写进市场规则**。港股的不同点：股价是港元而联想等公司的财报是美元，估值前要换汇率；交易日历和收盘时间不同；业绩按披露易公告，没有 8-K；大多不给数字化指引；免费的一致预期少。这些差异放在公共代码的市场规则里，各模块按股票代码后缀（`.HK`）取用。
10. **借 UZI-Skill 的护栏，不借它的打分**。UZI 在“防止模型乱写”上积累了不少做法，值得搬；但它的核心产出是 65 位评委投票和 19 维综合分，这和我们“只给带依据的价位”相反。具体取舍见下表。

### 参考 UZI-Skill：借什么、不借什么

依据：读了 `~/Downloads/UZI-Skill`（3.9.4 版）的 `skills/deep-analysis/SKILL.md` 和 `scripts/lib/`，以及 2026-10-30 在你 Mac 上跑 INTC 的结果。

| UZI 的做法 | 出处 | 本项目怎么用 |
|---|---|---|
| 脚本算数、模型写判断，分两段执行 | `SKILL.md` 两段式执行 | 已采用，见决策 1 |
| 出报告前机械自查，严重问题拒绝出 HTML | `lib/self_review.py` | 采用，放进 [REPORT] |
| 解读记下所依据数据的指纹，数据变了就作废 | `lib/agent_review.py` | 采用，见 [INV-11] |
| 数据缺口交给模型定点补，补不到要明确登记，不准用默认值 | `HARD-GATE-DATAGAPS` | 采用，放进 [QA] 和 [SKILL] |
| 禁止编造原始数据里没有的事实和关联 | `HARD-GATE-FACTCHECK` | 采用，并升级为程序检查（数字必须有出处） |
| 禁用“基本面良好、前景广阔、值得关注”，矛盾必须写出来 | `SKILL.md` 硬性门控 4、5 | 采用，放进 [REPORT] 自查和 [SKILL] 写作规则 |
| 财报前预案：一致预期、行业观察指标、三情景、历史波幅 | `fin-methods/earnings-preview.md` | 采用，新增流程 ⑩ |
| 来源登记表和网络预检 | `lib/data_source_registry.py`、`lib/network_preflight.py` | 采用，放进 [DATA] |
| 65 位评委投票、19 维综合打分 | `investor-panel`、`task2-dimension-scoring.md` | 不用。只保留四个视角的清单，不投票、不打分 |
| 数据覆盖率只在低于 40% 时算严重 | `self_review.check_coverage_threshold` | 不用。INTC 61% 照样出了报告；本项目必需字段缺一个就停 |
| 以雅虎财经为主要美股来源 | `scripts/fetch_*.py` | 不用。云端被拦，Mac 上也拿到了财报前的旧价格 |
| A 股游资席位、杀猪盘识别等 | `lhb-analyzer`、`trap-detector` | 不用，与美股大盘股无关 |
| 一个 1100 行、十几道门控的技能文件 | `skills/deep-analysis/SKILL.md` | 不用。门控写成代码检查，技能文件只写步骤 |

## 3. 模块

公共代码放在 `src/stockdesk/shared/`（数据模型：快照、来源、财报包、买点；错误码与提示；市场规则：美股和港股的交易日历、收盘时间、货币、披露方式），所有模块都可以引用；`src/stockdesk/shared/` 不得引用任何其他模块。入口文件 `src/stockdesk/__main__.py` 只能引用 [CLI]。

### [R-OUT] Claude 项目

- 职责：你看到结果的地方。报告发布成报告页；周五复盘有变化时，在项目对话里发一条提醒。
- 调用：无
- 验收：[AT-5]、[AT-8]

### [SKILL] Claude 技能

- 职责：四个技能文件，规定 Claude 每次按同样的步骤做事。技能只负责“读和判断”，不自己算价位。
- 位置：`skills/`（Markdown，不是 Python 代码）
- 调用：[CLI]、[R-WEB]、[R-OUT]
- 验收：[AT-5]、[AT-8]
- 四个技能：
  - `earnings-preview`：财报前 3 天，`sd preview` → 把三种情景各对应到买点动作 → 发布预案页。
  - `earnings-review`：取数（云端 WebFetch 后 `sd import`，Mac 上 `sd fetch`）→ `sd pack` → 读电话会实录和财报包，写“发生了什么、市场担心什么、指引意味着什么” → 给出前瞻 EPS 与 PE 假设 → `sd zones` → `sd report` → 发布报告页 → `sd watch save`。
  - `buy-zones`：不在财报季时单独更新某只股票的三档，步骤是取数、假设、`sd zones`、`sd watch save`。
  - `weekly-check`：取全部观察清单股票的周收盘和宏观数据 → `sd check` → 有提醒才发消息。
- 要点：
  - 每次写假设都要写一句理由，例如“FY27 EPS 取 1.75，低于财报前一致预期 2.14，因为 Q4 毛利率指引 38%”。
  - 抓网页时把来源网址和页面上的数据日期一起记下；拿不到就留空，交给 [QA] 判定，不要猜。
  - [QA] 拒绝时按缺口清单定点补抓；补不到的非关键字段用 `sd import --gap-ack` 登记原因。
  - 解读必须过四个视角：价值（估值分位）、成长（营收和指引）、趋势（均线和支撑）、宏观（利率、VIX、信用利差）。每个视角只引用财报包里的数字；视角之间矛盾时写出矛盾本身。
  - 解读文件开头写明所依据的财报包指纹（`sd pack` 输出里的 `pack_hash`）。
  - 拿不到电话会实录时，改读公司 IR 的业绩演示材料和公告，并在解读开头写“未取得电话会实录”。

### [SCHED] 定时任务

- 职责：每周五美东收盘后跑 `weekly-check`；观察清单里的公司财报前 3 天跑 `earnings-preview`，发财报的次日跑 `earnings-review`。优先用 Claude 项目的定时任务，不需要额外服务器。
- 调用：[SKILL]
- 验收：[AT-8]

### [CLI] 命令行 sd

- 职责：唯一的程序入口。解析参数，调用对应模块，结果以 JSON 输出给 Claude，以简短中文摘要输出给人。
- 代码目录：`src/stockdesk/cli/`
- 调用：[DATA]、[EARN]、[ZONES]、[WATCH]、[REPORT]
- 验收：[AT-1]、[AT-3]、[AT-4]、[AT-5]、[AT-6]、[AT-7]、[AT-10]、[AT-11]、[AT-12]
- 接口：见第 4 节“命令行”。
- 要点：
  - 每个命令都支持 `--replay <案例名>`，从 `tests/cases/` 读固定快照，用于测试和演示。
  - 出错时打印错误码、原因和下一步，退出码非 0。

### [R-WEB] 公开网页

- 职责：云端唯一的取数途径，由 Claude 用 WebFetch 读取。已验证能读：stockanalysis.com（美股 `/stocks/<代码>/`，港股 `/quote/hkg/<代码>/`，含 history、financials、forecast、statistics）、marketbeat、stocktitan、SEC 原文页面。港股公告用披露易网页，电话会实录和 IR 材料用公司官网。
- 调用：无
- 验收：[AT-5]
- 要点：网页可能有缓存，页面上的数据日期必须一起记下，交给 [QA] 判断时效。

### [R-MKT] 行情与预期接口

- 职责：Mac 上直连的行情库。yfinance（美股、港股日线，代码如 `0992.HK`）、AKShare（港股日线和财务摘要，东方财富等国内来源）。也可直接抓 stockanalysis 页面作为第二来源做交叉核对。
- 调用：无
- 验收：[AT-10]

### [R-SEC] SEC EDGAR

- 职责：财报数字的标准来源。8-K 的新闻稿附件（Ex-99.1）、10-Q、10-K、XBRL 三表。免费，需要在请求头里写联系邮箱。
- 调用：无
- 验收：[AT-10]

### [R-HKEX] 港交所披露易

- 职责：港股财报数字的标准来源：业绩公告、中期报告、年度报告。免费。联想按季度发业绩公告，下一次是 2026-11-19。
- 调用：无
- 验收：[AT-10]

### [R-MACRO] 宏观数据

- 职责：10 年期美债利率、VIX、高收益债信用利差，用于主报告第 8 章的加仓和降风险信号；美元兑港元汇率，用于港股估值换算。
- 调用：无
- 验收：[AT-10]

### [DATA] 数据网关

- 职责：唯一访问外部数据的代码模块。两种进数方式：`fetch` 直连来源（Mac），`import` 接收 Claude 抓好的 JSON（云端）。统一写成快照，每个字段带来源和时间。
- 来源登记：`config/sources.toml` 列出每个来源能给哪些字段、哪种环境能连、优先级。`sd doctor` 做网络预检，判断当前是云端还是 Mac、哪些来源能连，结果写进 `data/network-profile.json`；`fetch` 按它选来源，全部连不上时返回 `SOURCE_BLOCKED` 并提示走 WebFetch 导入。
- 代码目录：`src/stockdesk/data/`
- 调用：[R-MKT]、[R-SEC]、[R-HKEX]、[R-MACRO]、[ST-SNAP]
- 验收：[AT-5]、[AT-10]
- 接口：

```text
doctor() -> NetworkProfile                        # 环境、各来源能否连通
fetch(ticker, kinds=["price","fundamentals","consensus","filing","macro"]) -> SnapshotRef
import_json(ticker, path, gap_ack=None) -> SnapshotRef   # 校验字段名、单位、日期格式；登记确认缺失的字段
```

- 要点：
  - 单位统一：金额用美元、不缩写（16.5B 存成 16500000000）；百分比存小数。
  - 抓取失败不重试三次以上，记录失败原因写进快照，让 [QA] 判断能否继续。

### [EARN] 财报包

- 职责：财报后，把一个季度整理成固定结构：实际 vs 预期、分部门、指引 vs 预期、现金与资本、一次性项目。财报前，生成预案：一致预期表、行业观察指标、乐观/基准/悲观三种情景及触发条件、过去 8 次财报后的股价反应。只组装和计算，不写判断。
- 代码目录：`src/stockdesk/earnings/`
- 调用：[QA]
- 验收：[AT-1]、[AT-2]、[AT-11]、[AT-12]
- 接口：

```text
build_pack(ticker, quarter, as_of) -> EarningsPack       # 字段见第 4 节，带 pack_hash
build_preview(ticker, quarter, as_of) -> EarningsPreview
```

- 要点：
  - GAAP 与 non-GAAP 各占一列，不合并。
  - 新闻稿里列出的“其他收益/损失”超过当季营业利润 10% 时，标为一次性项目，并给出剔除后的营业利润。
  - 行业观察指标写在 `config/watch_metrics.toml`，先覆盖 AI 产业链：半导体（毛利率、库存天数、产能利用率）、云（积压订单、capex、云业务利润率）、网络和光模块（800G/1.6T 出货、大客户集中度）、电力（在手订单、装机）。
  - 预案里拿不到的一致预期标“需补充”，不用历史增速外推的数字冒充预期。

### [ZONES] 买点规则

- 职责：把 Claude 的假设（前瞻 EPS、合理 PE 区间）和 [VAL]、[TECH] 的价位合成 A/B/C 三档、仓位、右侧信号和失效位。纯函数，不读写文件。
- 代码目录：`src/stockdesk/zones/`
- 调用：[VAL]、[TECH]
- 验收：[AT-3]、[AT-4]、[AT-12]
- 接口：

```text
compute_zones(ticker, as_of, eps_fwd, pe_range, rules) -> ZonePlan | Refusal
```

- 要点：规则见第 4 节“买点规则”。每一档必须写锚点，锚点只能是 [TECH] 或 [VAL] 返回的某个具体数值。

### [WATCH] 观察清单

- 职责：保存每只股票当前的三档、失效位、依据、下次财报日，旧版本留历史；周五复盘时用最新周收盘对照，产出提醒列表。
- 代码目录：`src/stockdesk/watch/`
- 调用：[QA]、[ST-WATCH]
- 验收：[AT-7]
- 接口：

```text
save(plan: ZonePlan, note) -> None
check(as_of) -> list[Alert]     # Alert: ticker, kind, price, level, reason
```

- 要点：提醒只在“状态变化”时发出：新进入某一档、新跌破失效位、宏观信号翻转、财报日在 7 天内。与上周相同的状态不重复提醒。

### [REPORT] 报告

- 职责：先自查，再把财报包、买点和 Claude 写的解读（Markdown）合成一页 HTML，样式与现有 GOOGL、INTC 财报页一致；每个数字悬停可见来源和日期。
- 代码目录：`src/stockdesk/report/`
- 调用：[ST-REPORT]
- 验收：[AT-6]
- 出报告前自查（任何一条严重问题都拒绝生成，错误码 `SELF_REVIEW_FAILED`，附问题清单和修法）：
  1. 解读正文里的数字都能在分析包里找到（否则 `UNSOURCED_NUMBER`）。
  2. 解读里的 `pack_hash` 与当前财报包一致（否则 `STALE_NOTES`）。
  3. 三档价格低于最新收盘且严格递减，仓位合计 100%。
  4. “数据截至”是最近一个交易日。
  5. 没有“基本面良好、前景广阔、值得关注”这类空话。
  6. 估值视角和趋势视角结论相反时，正文里有“矛盾”一段。
  7. 登记为确认缺失的字段显示为“—”并注明原因。
- 要点：报告顶部固定写“数据截至”日期和“不构成投资建议”。

### [VAL] 估值

- 职责：给定前瞻 EPS 和 PE 区间，算出对应价格；提供近 3 年 PE 的分位数和同行 PE，供 Claude 和 [ZONES] 参考。
- 代码目录：`src/stockdesk/valuation/`
- 调用：[QA]
- 验收：[AT-3]、[AT-12]
- 要点：EPS 的货币与股价货币不同时（联想财报是美元、股价是港元），先按估值日的汇率换算，并在输出里写明汇率和来源。

### [TECH] 技术位

- 职责：从日线算 50 日线、200 日线、近一年被多次测试的支撑位、52 周高点及回撤 35%、40%、45% 的价位、最新日收盘和周收盘。
- 代码目录：`src/stockdesk/technicals/`
- 调用：[QA]
- 验收：[AT-3]、[AT-12]
- 要点：“多次测试的支撑”定义为近 250 个交易日里，日最低价落在同一 2% 区间内至少 3 次、且之后反弹超过 5% 的价位。

### [QA] 数据守门

- 职责：分析内核读数据的唯一通道。按调用方需要的字段清单，检查覆盖率、时效、来源一致性；通过则返回数据，不通过则返回拒绝、原因和缺口清单（每个缺失字段建议去哪个来源补）。
- 代码目录：`src/stockdesk/qa/`
- 调用：[ST-SNAP]
- 验收：[AT-1]、[AT-2]、[AT-3]、[AT-4]、[AT-7]、[AT-11]、[AT-12]
- 接口：

```text
require(ticker, fields, as_of) -> Dataset | Refusal
# Refusal.code ∈ STALE_PRICE · DATA_INCOMPLETE · SOURCE_CONFLICT · NO_SNAPSHOT
```

- 要点：
  - 各命令的必需字段见第 5 节，分“关键”和“非关键”。阈值写在配置文件里。
  - 非关键字段登记为确认缺失后可以放行，报告里显示为缺失；关键字段（价格、营收、EPS、下季指引）不能登记跳过。

- 调用：无
- 验收：[AT-1]、[AT-10]

- 调用：无

- 调用：无

## 4. 接口与协议

### 命令行

| 命令 | 做什么 | 主要输出 |
|---|---|---|
| `sd doctor` | 网络预检：当前环境、各来源能否连通 | 网络概况 |
| `sd fetch INTC` | Mac 上直连来源抓数据 | 快照路径、各字段覆盖情况 |
| `sd import INTC fetched.json` | 登记 Claude 抓好的网页数据 | 快照路径、校验结果 |
| `sd preview INTC --quarter 2026Q4` | 财报前预案 | 预案 JSON |
| `sd pack INTC --quarter 2026Q3` | 组装财报包 | 财报包 JSON（含 `pack_hash`） |
| `sd zones INTC --eps 1.75 --pe 38-45` | 算三档买点 | 买点 JSON |
| `sd report INTC --notes notes.md` | 合成 HTML 报告 | 报告路径 |
| `sd watch save INTC` | 把最新买点写进观察清单 | 新旧对比 |
| `sd check` | 周五复盘 | 提醒列表（可能为空） |
| `sd demo intc-q3-2026` | 用固定案例跑完 pack → report | 报告路径 |

所有命令加 `--json` 时只输出 JSON，供技能读取；加 `--replay <案例>` 时只读 `tests/cases/` 里的快照。

### 财报包字段

营收、GAAP EPS、non-GAAP EPS、毛利率（GAAP 与 non-GAAP）、营业利润、分部门营收和利润、下季指引（营收、毛利率、EPS 的区间）、对应的一致预期、自由现金流、capex、回购、增发和发债、一次性项目列表。每个字段是 `{value, unit, source_url, as_of, fetched_at}`。

### 买点规则

| 档位 | 价位锚点（取规则允许的最近一个） | 估值校验 | 默认仓位 | 何时可用 |
|---|---|---|---|---|
| A | 多次测试的支撑或 50 日线 | 不高于近 3 年 PE 中位 | 25–30% | 财报跳空后等 2 个交易日 |
| B | 200 日线或估值区间下沿 | 接近近 3 年 PE 低分位 | 30–35% | 宏观无降风险信号 |
| C | 52 周高点回撤 35–45% | 危机估值 | 40% | 只在 VIX > 35 或标普自高点 −15% 时 |
| 右侧 | 周收盘重新站回财报前收盘价 | — | 补回未买部分 | 趋势修复确认 |
| 失效位 | 关键支撑下方 | 投资逻辑被证伪 | 停止加仓、复盘 | 周收盘跌破 |

- 三档价格严格递减，且都低于最新收盘；仓位合计 100%。
- 离 52 周高点不到 19% 的股票用 2-3-5 分配，并留一半作恐慌储备（沿用主报告第 8 章）。
- 参数写在 `config/rules.toml`，修改参数视为改规则，需要在报告里注明规则版本。

### 港股差异

| 项目 | 美股 | 港股 |
|---|---|---|
| 代码 | `INTC` | `0992.HK` |
| 财报标准来源 | SEC 8-K 附件、10-Q | 披露易业绩公告 |
| 价格货币 / 财报货币 | 美元 / 美元 | 港元 / 视公司而定（联想是美元） |
| 收盘时间 | 美东 16:00 | 香港 16:10（收市竞价后） |
| 数字化指引 | 多数公司有 | 大多没有，作为非关键字段 |
| 免费一致预期 | stockanalysis、marketbeat | stockanalysis 港股 forecast 页，覆盖较少，作为非关键字段 |

### 错误码

| 错误码 | 含义 | 下一步 |
|---|---|---|
| `NO_SNAPSHOT` | 这只股票没有快照 | 先 `sd fetch` 或 `sd import` |
| `STALE_PRICE` | 最新价格早于上一个交易日收盘 | 重新取价格 |
| `DATA_INCOMPLETE` | 必需字段缺失（附缺口清单） | 按清单补抓；非关键字段补不到时用 `sd import --gap-ack` 登记 |
| `SOURCE_CONFLICT` | 两个来源差异超过阈值（会列出两个值） | 查原文后用 `sd import` 覆盖并注明 |
| `UNSOURCED_NUMBER` | 解读里有分析包找不到的数字 | 改正文，或补数据 |
| `STALE_NOTES` | 解读依据的是旧的财报包 | 按新数据重写解读 |
| `SELF_REVIEW_FAILED` | 出报告前自查有严重问题（会列出） | 按清单逐条修 |
| `SOURCE_BLOCKED` | 当前环境连不上该来源 | 云端改用 WebFetch + `sd import` |
| `FX_MISSING` | 股价与财报货币不同，但缺当日汇率 | 补抓汇率 |

## 5. 配置与数据

**快照格式**（每个字段一条）：

```json
{"field": "revenue", "period": "2026Q3", "value": 16500000000, "unit": "USD",
 "source_url": "https://www.sec.gov/...ex99-1.htm", "as_of": "2026-09-27",
 "fetched_at": "2026-10-30T08:00:00Z", "via": "import"}
```

**各命令的必需字段**（[QA] 据此判定）：

| 命令 | 美股关键字段 | 港股关键字段 | 非关键字段（可登记缺失） |
|---|---|---|---|
| `pack` | 营收、EPS（两种口径）、毛利率、下季指引、对应一致预期 | 营收、EPS、毛利率 | 电话会实录、分部门数据、港股的一致预期和指引 |
| `zones` | 近 260 个交易日日线、最新收盘、前瞻 EPS、近 3 年 PE | 同左，另加当日汇率（货币不同时） | 同行 PE |
| `check` | 每只股票最新周收盘、10 年期利率、VIX | 同左 | 信用利差 |

**阈值**（`config/qa.toml`）：价格两个来源差异 > 1% 记为冲突；财报数字差异 > 0.5% 记为冲突。

**观察清单列**：代码、A 档区间、B 档区间、C 档区间、右侧价、失效位、仓位分配、锚点说明、EPS 假设、PE 假设、规则版本、更新日期、下次财报日、上次状态。

## 6. 不变量

### [INV-1] 每个数字都带来源网址和数据日期

- 检查：快照写入时校验 `source_url`、`as_of`、`fetched_at` 三个字段非空；报告里每个数字带来源属性。
- 验收：[AT-1]、[AT-10]

### [INV-2] 价格过期就不出买点和复盘结论

- 检查：[QA] 用交易日历比较价格的 `as_of` 与上一个交易日；`zones` 和 `check` 遇到 `STALE_PRICE` 必须拒绝。
- 验收：[AT-4]

### [INV-3] 必需字段不全就不给结论，并说清缺什么

- 检查：[QA] 按第 5 节的清单检查；拒绝信息里列出缺失字段名。
- 验收：[AT-4]

### [INV-4] 两个来源打架时两个值都列出，不悄悄挑一个

- 检查：同一字段有两个来源且差异超过阈值时返回 `SOURCE_CONFLICT`，附两个值和两个网址。
- 验收：[AT-4]

### [INV-5] 模型不编数字

- 检查：价位只由 [ZONES] 输出；[REPORT] 渲染前比对正文数字与分析包。
- 验收：[AT-3]、[AT-6]

### [INV-6] 每一档都有锚点和仓位，失效位按周收盘

- 检查：`ZonePlan` 的数据模型要求每档有 `anchor`、`size`；失效位类型固定为 `weekly_close_below`。
- 验收：[AT-3]

### [INV-7] GAAP 与 non-GAAP 分开，一次性项目单独标出

- 检查：财报包模型里两种口径是独立字段；一次性项目规则见 [EARN]。
- 验收：[AT-2]

### [INV-8] 分析内核不联网

- 检查：测试时禁用 socket，分析内核的全部测试必须在断网下通过；`make arch` 禁止内核引用网络库。
- 验收：[AT-9]

### [INV-9] 不接券商、不下单、不存账户凭据

- 检查：依赖白名单里没有任何券商 SDK；代码里搜不到下单相关接口。
- 验收：[AT-9]

### [INV-10] 代码只允许图上的调用关系

- 检查：`make arch` 检查所有 import，只允许图上画了“代码调用”箭头的方向。
- 验收：[AT-9]

### [INV-11] 解读必须对应当前数据

- 检查：解读文件记录 `pack_hash`；[REPORT] 自查时与当前财报包比对，不一致返回 `STALE_NOTES`。
- 验收：[AT-6]

### [INV-13] 货币不同必须换算

- 检查：[VAL] 比较 EPS 和股价的货币字段，不同时必须取到当日汇率，否则返回 `FX_MISSING`；输出里写明所用汇率和来源。
- 验收：[AT-12]

### [INV-12] 补不到的数据显示为缺失，不用默认值顶替

- 检查：数据模型里缺失值是独立状态，不是 0 或空字符串；关键字段不接受缺失登记。
- 验收：[AT-4]
